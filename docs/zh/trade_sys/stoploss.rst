止损/止赢策略|ST
=================

.. Note::

    Hikyuu中将止损和止盈分别作为交易系统的两个策略组件。两者之间在概念和执行上有所区别。比如，一般系统通常在使用跟随性的指标曲线作为止盈退出时，经常会发生滞后的情况，原本希望收盘价低于指标时卖出止盈，但实际上指标和收盘价同时都在下跌，这样实际的退出发生在收盘价向下穿越指标线时，这样造成滞后反映，另外，如果在盘中实时跟踪，由于收盘价不停的变动，止损的指标线也会发生变动，这样会出现噪音误判，导致一般系统里实盘和回测的结果出现偏差。Hikyuu里，当前Bar里止损/止盈都是不变的固定是上一时刻的值，同时，Hikyuu里系统是保证止盈始终单调递增的！比如某个指标值，前天值为11，昨天的值为9，今天的收盘价10，那么这个指标作为止损部件（今日收盘价10大于止损价9），不会触发退出，而作为止盈部件，系统则会发出卖出指示，因为当前的收盘价已经低于11。
    

常用止损/止赢策略
-----------------

止损是指买入后，价格的走势和预期相反，当价格低于某一水平时卖出，防止进一步的损失。
止赢是在买入后，价格符合预期走势，当价格回落至某一水平时卖出，获得足够的收益。
进行交易时，即可使用相同的止损和止赢策略，也可使用不同的止损和止赢策略，如使用固定百分比3%作为止损，使用吊灯安全线作为止赢。

固定百分比止损
^^^^^^^^^^^^^^

.. py:function:: ST_FixedPercent([p=0.03])

    固定百分比止损策略，即当价格低于买入价格的某一百分比时止损
    
    .. note::
        当止损价无法用最小变动单位表示时（价格过低，例如 ``price=0.01, p=0.5`` 舍入到 0.01 刻度后经钳制为 0，或 ``price=0.006, p=0.03`` 经钳制后为负），视为无效，交易照常执行但**没有止损保护**；``p=1.0`` 表示无止损（该价位永不可达）。
    
    :param float p: 百分比(0,1]
    :return: 止损/止赢策略实例

技术指标止损
^^^^^^^^^^^^

.. py:function:: ST_Indicator(ind)

    使用技术指标作为止损价。如使用10日EMA作为止损：::
    
        ST_Indicator(EMA(CLOSE(), n=10))

    .. note::
        指标在预热期（如前 N 根 bar）或该 bar 无有效值（NaN/inf）时视为无效：作为止损时交易照常执行但**没有止损保护**（该仓位终身无静态止损，请配合止盈或信号卖出），作为止盈时该 bar 不止盈。

    :param Indicator ind: 指标公式
    :return: 止损/止赢策略实例

亚历山大.艾尔德安全地带止损
^^^^^^^^^^^^^^^^^^^^^^^^^^^^    

.. py:function:: ST_Saftyloss([n1=10, n2=3, p=2.0])

    参见《走进我的交易室》（2007年 地震出版社） 亚历山大.艾尔德(Alexander Elder) P202
    计算说明：在回溯周期内（一般为10到20天），将所有向下穿越的长度相加除以向下穿越的次数，
    得到噪音均值（即回溯期内所有最低价低于前一日最低价的长度除以次数），并用今日
    最低价减去（前日噪音均值乘以一个倍数）得到该止损线。为了抵消波动并且保证止损线的
    上移，在上述结果的基础上再取起N日（一般为3天）内的最高值

    :param int n1: 计算平均噪音的回溯时间窗口，默认为10天
    :param int n2: 对初步止损线去n2日内的最高值，默认为3
    :param double p: 噪音系数，默认为2；必须为有限值且 > 0，否则构造时抛出异常（p<=0 会让止损线跑到价格上方，p 为 NaN 会让所有 bar 被过滤而静默无止损）
    :return: 止损/止赢策略实例
    

自定义止损/止赢策略
-------------------

自定义止损/止赢策略接口：

* :py:meth:`StoplossBase._get_price` - 【必须】计算原始多头止损价格
* :py:meth:`StoplossBase._get_short_price` - 【必须】计算原始空头止损价格（默认返回0；空头止损价须高于计划交易价）
* :py:meth:`StoplossBase._calculate` - 【必须】子类计算接口
* :py:meth:`StoplossBase._clone` - 【必须】克隆接口
* :py:meth:`StoplossBase._reset` - 【可选】重载私有变量

止损价返回值契约与系统行为
--------------------------

``_get_price`` / ``_get_short_price`` 的调用频率取决于本实例的用途：**用作止损时只在开仓路径调用**（每笔交易约一到两次，止损价确定后写入持仓记录，持仓期不再调用）；**用作止盈时持仓期间每个 bar 调用一次**（止盈是移动棘轮，每 bar 需重新取价）。返回值含义与系统后续行为如下：

* **返回值 > 0**：有效的止损/止赢价格。该价格应使用与 ``setTO`` 传入的 KData 相同的（复权）价格坐标，系统内部会将其映射回原始价格坐标。
* **返回值 = 0**：该 bar 无止损（策略显式声明）。交易照常进行，但不设止损保护（头寸按满额计划价风险计算）。
* **返回值为负值或非有限值（NaN/inf）**：视为无效，等价于“无止损”——交易仍然执行（多头买入、空头开仓），头寸同样按满额计划价风险计算（风险型资金管理会自动缩小头寸）。注意：止损价在入场时确定、持仓期不更新，因此该仓位在整个持有期内都没有静态止损保护，须依赖止盈（TP）、盈利目标或信号卖出退出。

在此基础上，系统还会做两类“无意义止损价”的裁决：

* **多头**：止损价不低于计划买入价时，放弃该笔买入（意味着该策略无法提供有效保护）。
* **空头**：止损价不高于计划交易价（含等于）时，放弃该笔卖空（否则建仓后下一 bar 即触发平空）。

以技术指标构造的止损（``ST_Indicator`` / ``ST_Saftyloss``）同样遵循上述契约：指标在预热期或该 bar 无有效值（NaN/inf）时视为无效——作为止损时仍然开仓但无止损，作为止盈则只是该 bar 无止盈。

上述“无止损开仓”与“放弃无意义止损价”均为正常处理，不产生警告日志；需要排查原因时可将系统参数 ``trace`` 设为 True 查看输出。

**作为止盈使用时的差异**：止盈复用同一基类及同一返回值契约，但返回值 0 或无效只表示“该 bar 无止盈”，不会跳过交易。

**止损为静态、止盈为移动**：止损价在入场时确定并写入持仓记录，持仓期间**不再随行情更新**（``ST_Indicator``、``ST_Saftyloss`` 用作止损时同样如此）。需要随行情移动的退出应使用止盈（TP）：其价格在持仓期间按“多头只升、空头只降”的棘轮规则维护，且仅在盈利条件下才平仓；部分卖出/平仓后若仍有持仓，止盈棘轮会以当时价格重新起算。

    .. py:method:: _get_price(self, datetime, price)
    
        【重载接口】计算原始多头止损价格，公共方法 get_price 会委托给该钩子。每个 bar 调用一次，返回的计划止损价须使用与 setTO 传入的 KData 相同的（复权）价格坐标（0 表示无止损）；负值或非有限值（NaN/inf）视为无效，系统按无止损继续开仓。

            一般情况下，止损/止赢的算法可以互换，但止损的 _get_price 可以传入计划交易的价格，比如以买入价格的30%做为止损。而止赢则不考虑传入的price参数，即认为price为0.0。实际上，即使止损也不建议使用price参数，如可以使用前日最低价的30%作为止损，则不需要考虑price参数。
        
        :param Datetime datetime: 交易时间
        :param float price: 计划买入的价格
        :return: 止损价格
        :rtype: float
