详细描述

Base class of the portfolio-level fund allocation (AF).

It contains three replaceable algorithm parts: L1 system-level allocation / L2 behavior-level conversion / L3 portfolio risk control (see the file comment for the details).

注解
It is used by the aggregate form (MultiSystem) only; the single-security form never calls this class. The running mode ("A" Signal Aggregation / "B" Fund Allocation / "C" Shared Account Compatibility) is owned by MultiSystem and passed into the hooks.

L1 skeleton: fill the L1 result by "sub-system index -> weight", and in mode B write contexts[i].quota (when fixed_amount>0 the fixed quota takes precedence, otherwise weight x the parent net assets).

注解
No normalization is performed, the weight semantics is fully decided by the subclass; the missing index (weights shorter than contexts) falls back to the equal weight.
The mode B quota sum (N x fixed_amount included) is bounded by max_total_position x net assets: the weight pricing is a proportion and is scaled down, while the fixed_amount pricing is an absolute amount and instead truncates the number of funded sub-systems (the rest get a zero quota).

L3 portfolio risk control clipping: mode A performs the portfolio dimension risk control (concentration / turnover, etc.); mode B can be disabled or only performs the total amount check.

注解
The single instrument concentration is limited by the parameter max_single_position (<=0 means no limit, >1 is clamped to 1, so the default 1.0 caps a single instrument at the net assets).
The clipping only shrinks: the budget released from a clipped instrument is not redistributed to the others, so after the total budget cap and this per-instrument cap the final gross exposure may stay well below max_total_position.

virtual void hku::AllocateFundsBase::_toTargets ( const Datetime & date,
const TradeManagerPtr & tm,
TradeSuggestionList & suggestions,
const Weights & sys_weight,
const KQuery & query,
const string & mode )
virtual

L2 behavior-level conversion: in mode A it converts the parent account quantity by the budget (weight / assets_ratio / fixed_amount, capped by max_total_position) and rewrites the number of every suggestion (a positive magnitude, the direction expressed by the type); in mode B the sub-system number is passed through.

注解
The number is always positive; a short suggestion is turned into a SELL to reduce to its target, a SELL/CLEAR closes the current holding.
Mode A prices a suggestion only when its system has a weight: a suggestion from a system absent from the weight table (a missing key, an empty table, or a cloned instance that is not the context one) is dropped with a warning. The weight table is produced by the matching L1 call on the same contexts.
fixed_amount > 0 skips the weight lookup entirely: every instrument gets that amount, and the total budget truncates the number of funded instruments in first-appearance order (the rest are driven flat) instead of shrinking every target.

The unified entry of L1/L2/L3, it is called by the aggregate System (MultiSystem).

Flow: L1 system-level allocation (nominal weight / real quota) -> L2 behavior-level conversion (mode A by proportion / mode B pass-through) -> L3 portfolio risk control clipping.

参数
datethe trade date
tmthe real trade account of the parent (aggregate) system
suggestions[in/out] the suggestions submitted by every sub-system; L2 rewrites them in place into the executable quantity of the parent account
contextsthe context of every sub-system (the virtual account funds / the mode B quota, etc.), used by L1 for the allocation
querythe query condition (the K-line type, etc.)
modethe running mode ("A"/"B"/"C"), owned by MultiSystem and passed to L1/L2/L3
