详细描述

Base class of the market environment strategy

注解
The external environment should have nothing to do with the concrete trading object
The environment is designed to be shared across systems (System shared_ev defaults to true): isValid takes a shared lock on every call while setQuery/reset take the exclusive lock, so all systems sharing one environment must use the same query, otherwise every differing setQuery reruns the full calculation under the exclusive lock

◆ _isValid()

virtual bool hku::EnvironmentBase::_isValid ( const Datetime & datetime,
price_t value ) const
virtual

Combination operators intentionally use different strategies over these refs, driven by their result semantics:

  • And / Multi / Div (intersection): two-pointer merge over the two ordered date_index maps, so there is no base side to pre-fill. And keeps only the dates valid (> 0) on both sides, with the value fixed to 1.0. Multi / Div keep only the dates where both sides agree: both valid (> 0) gives the product / ratio, both invalid (< 0) gives its negation (kept negative so that the day stays invalid) - a disagreement (mixed sign) or a zero side carries no combined strength and is left out.
  • Add / Sub (ev1 base + ev2 align): every date (valid or not) of ev1 and ev2 belongs to the result, so ev1 is laid down as the base and ev2 is aligned against it; ev1-only dates need no work and ev2-only dates go through _addValid. The value is the sum (Add) / the difference (Sub), an ev2-only date contributing -ev2 to Sub.
  • Or (union of valid): a date is kept iff it is valid on at least one side, with the value fixed to 1.0, so both maps are walked and the date is pushed only when a side is valid. Do NOT "unify" these: a laydown for Or would add ev1's invalid dates as 0.0 to the output date set; an intersection for Add/Sub would drop ev1-only/ev2-only dates; a laydown for And/Multi/Div would wrongly keep ev1-only dates. Each file's _calculate spells out its own branch. The subclass validity-rule hook, called by isValid for every date registered through _addValid
    参数
    datetimethe queried date
    valuethe stored value of the date
    返回
    true valid | false invalid; the default rule is "the value is finite and > 0"
    注解
    The System judges the market validity solely through isValid (one call per bar), so overriding this hook directly changes the trading behavior
    Override it to apply a custom rule based on the concrete ev value; the combination operators keep using the built-in "> 0" rule on their sides

◆ clone()

EnvironmentPtr hku::EnvironmentBase::clone ( )

Clone operation

注解
Unlike the other trading-system parts, the Environment is not bound to a specific instrument and can be shared, so essentially the clone operation is not needed here; it exists only for the consistency and the possibly existing special scenarios.
The subclass _clone callback is invoked without holding the mutex, so that it may reach the GIL (or re-enter this object) without risking a lock-order deadlock.
