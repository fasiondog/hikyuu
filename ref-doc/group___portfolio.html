Portfolio running in mode A "Signal Aggregation" (the signal sources + the parent uniform ordering) 

Description of the rebalancing mode adjust_mode:
 - In the "query" mode it follows the ktype in the input parameter query; at this time
adjust_cycle determines the cycle interval with the ktype in query;
 - In the "day" mode adjust_cycle is the number of the days between the rebalancing;
 - In the "week" | "month" | "quarter" | "year" mode, adjust_cycle is the corresponding N-th day
of every week, the n-th day of every month, the n-th day of every quarter and the n-th day of
every year; when delay_to_trading_day is false, the rebalancing is skipped if that day is not a
trading day; when delay_to_trading_day is true, it is postponed to the first trading day within
the current cycle if that day is not a trading day
注解
The sub-systems always use their own shadow accounts (TM_SUB, shared_tm=false), so the real account of the parent is only touched by the orders of the parent itself. The suggestions are converted into the target positions by the AF L2 (weight x net exposure ratio x the parent net assets, aggregated per instrument) and the L3 portfolio risk control applies. On a rebalancing day a sub-system the SE does not admit contributes a zero signal (its instruments drop out of the parent target); the shadow itself keeps running.
参数
tmtrade account
sesystem selector
afthe portfolio-level fund allocation algorithm (AF, carrying L1/L2/L3), equal weight by default
adjust_cyclethe rebalancing cycle (affected by adjust_mode), 1 by default; a negative value throws at set time, 0 is warned and treated as 1 at readyForRun, and a value that can never reach a driven day of the period is warned but kept
adjust_modethe rebalancing mode "query" | "day" | "week" | "month" | "quarter" | "year"
delay_to_trading_daywhen it is true, it is postponed to the first trading day within the current cycle if the rebalancing day is not a trading day
trade_on_closeexecute the trade at the close
sell_at_not_selectedwhether to force selling the stocks not selected on the rebalancing day, false by default
sub_init_cashthe signal cash of every sub-system shadow account (never reset, the shadow runs continuously)
返回

Description of the rebalancing mode adjust_mode:
 - In the "query" mode it follows the ktype in the input parameter query; at this time
adjust_cycle determines the cycle interval with the ktype in query;
 - In the "day" mode adjust_cycle is the number of the days between the rebalancing;
 - In the "week" | "month" | "quarter" | "year" mode, adjust_cycle is the corresponding N-th day
of every week, the n-th day of every month, the n-th day of every quarter and the n-th day of
every year; when delay_to_trading_day is false, the rebalancing is skipped if that day is not a
trading day; when delay_to_trading_day is true, it is postponed to the first trading day within
the current cycle if that day is not a trading day; for example, if the rebalancing is specified
on the 1st day of every month but the 1st is not a trading day, it is postponed to the first
trading day of that month
注解
In the mode without a fund allocation algorithm, only all buying and selling at the open or all buying and selling at the close is supported!
Returns MultiSystemPtr running in mode C "Shared Account Compatibility" (the legacy Portfolio behavior): the sub-systems share the real account of the parent and are sized by their own MM (so they compete for the same cash, in the pool admission order), the AF is only the mode carrier here (L1 takes no quota, L2 needs no conversion, L3 is off by default) and the parent never places an extra order.
警告
With the default sell_at_not_selected=false, a sub-system that the SE stops admitting while it still holds is driven ONE last time and then FROZEN: its stop-loss, profit goal and sell signals stop working and the position is never closed (the legacy engine behavior). Set keep_watch_force_sell=true to keep driving it until it is flat, or sell_at_not_selected=true to liquidate it at once.
注解
On a rebalancing day a sub-system that the SE stops admitting leaves the running pool no matter whether it still holds: sell_at_not_selected=true liquidates it at once, while the default false gives it ONE last drive (so a sell signal of that very day is still realized) and then stops following it (the position is left as the legacy engine did), unless keep_watch_force_sell keeps it driven. The driven set follows the SE semantics: an "all selected" SE (e.g. SE_Fixed) degenerates mode C into driving every sub-system every day.
sys_use_self_tm is kept for the signature compatibility only: in mode C the sub-systems always share the real account of the parent, so it is ignored with a warning.
