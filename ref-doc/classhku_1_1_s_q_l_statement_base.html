getColumn NULL mapping

A SQL NULL column read is mapped to the type's Null sentinel so it stays distinguishable from real 0 values:

  • signed integers (any width): Null<T>(), i.e. std::numeric_limits<T>::max()
  • uint64_t: std::numeric_limits<uint64_t>::max()
  • double/float: Null<double>() (quiet NaN)
  • Datetime: Null<Datetime>()
  • text: an empty string (text has no sentinel, NULL is indistinguishable from empty)
  • blob: throws null_blob_exception; an empty (zero-length) blob returns an empty result instead, so NULL and empty blobs stay distinguishable
注解
An actually stored maximum value of an integer type is indistinguishable from NULL, which is inherent to the Null sentinel scheme

◆ bind_params()

void hku::SQLStatementBase::bind_params ( const BoundValues & params)
inline

Bind a full set of condition values to the anonymous placeholders of the statement, in order

The values are bound at index 0, 1, ... so they line up with the ? written left to right by renumberPlaceholders. It has to be the only binder of the statement: mixing it with the index-based bind calls shifts every following value silently on the drivers that do not check the binding order.
