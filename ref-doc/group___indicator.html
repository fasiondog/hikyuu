The built-in common indicators and the infrastructure for defining and implementing new indicators

It contains the indicator base class definition, some common indicators and the indicator creation functions

注解
In a client program it is recommended to use the indicator creation functions as much as possible to create the concrete indicator to be called, so as to avoid wrong memory allocation and release
Example:
Indicator ma = MA();
std::cout << ma.name() << std::endl;

ADX average directional index 

ADX (Average Directional Index) is a trend strength indicator, it does not distinguish the rising
or falling direction, it only judges whether there is a trend.

The original formula of Wilder is used, with the period N = 14:

1. TR true range (the maximum of the three choices):
   TR = max(H-L, |H-C_prev|, |L-C_prev|)

2. DM directional movement:
   +DM = H - H_prev (if H > H_prev and the upward move > the downward move), otherwise 0
   -DM = L_prev - L (if L < L_prev and the downward move > the upward move), otherwise 0

3. Wilder smoothing (a simple average of N periods at the beginning, recursive afterwards):
   ATR_t = ATR_{t-1} × (N-1)/N + TR_t/N
   S+DM_t = S+DM_{t-1} × (N-1)/N + +DM_t/N
   S-DM_t = S-DM_{t-1} × (N-1)/N + -DM_t/N

4. ±DI directional indicator (percentage 0~100):
   +DI = (S+DM / ATR) × 100
   -DI = (S-DM / ATR) × 100

5. DX directional indicator:

- 1: +DI (upward directional line, bull power)
- 2: -DI (downward directional line, bear power)

Judgment criteria:
- ADX >= 25: a clear one-sided trend exists (either rising or falling)
- ADX < 25: no trend, range-bound oscillation
- The larger the ADX value, the stronger the trend

Cross-section information coefficient (IC) of a factor over a stock set.

Each trading day, the factor values and the n-day return of every stock are collected into a cross-section and their Spearman (default) or Pearson correlation is computed.

注解
Alignment: the daily pair is (factor observed at t - n, return over [t - n, t]). By default the result is stored at index t (the observation completion date), so the current value is readable without future data — the "current IC" convention. Set strict = true to re-index by the factor observation date (t - n), matching the industry-standard forward IC definition; in that mode the trailing n values are Null because their forward returns are not yet realized.
Choosing strict: backtests that feed IC into MF_ICWeight / MF_ICIRWeight or any live-decision path should keep the default non-strict mode — strict IC[t] uses returns over [t, t+n] and would introduce look-ahead bias if consumed at t. Use strict = true only for offline factor analysis or when aligning with published (academic / industry) IC numbers that are indexed by factor date.

Indicator HKU_API hku::ISLIMITDOWN ( )

#include </Users/fasiondog/workspace/hikyuu/hikyuu_cpp/hikyuu/indicator/crt/ISLIMITDOWN.h>

Indicator for judging whether a stock is limit down

Judge whether the close price of the day reaches the limit-down price according to the different stock types:

  • Ordinary A-share stock: the limit-down range is 10%
  • Beijing Stock Exchange stock: the limit-down range is 30%
  • ChiNext / STAR Market stock: the limit-down range is 20%
  • ST stock: the limit-down range is 5%, but it is not handled yet because the historical date information of the ST identifier is missing

Limit-down judgment logic: close price of the day <= close price of the previous day × (1 - limit-down range)

Notes:

  • The first K-line data is marked as discard because the previous day data is missing
  • An unsupported stock type returns the non-limit-down state by default
  • The calculation result is a boolean value: 1 means limit down, 0 means not limit down
  • The ranges follow the current rules of each board, without date segmentation: the ChiNext stocks were limited to 10% before 2020-08-24 and a new listing has no range limit in its first days, both of which are judged by the current range
  • The judgment runs on the backward-adjusted (BACKWARD) close series: a no-recover context is re-fetched internally with the same query so that the comparison stays continuous across ex-right dates
Example:

// Create the limit-down judgment indicator


Indicator limit_down = ISLIMITDOWN();


 


// Judge the given K-line data


KData kdata = sm["sh000001"].getKData(KQuery(-100));


Indicator result = ISLIMITDOWN(kdata);


 


// Get the judgment result


for (size_t i = 0; i < result.size(); ++i) {


    if (result[i] == 1.0) {


        cout << "day " << i << " is limit down" << endl;


    }


}

It returns the complete regression result, including the coefficients, the residual sequence, the residual sum of squares and the R² value

参数
stkthe stock object
queryK-line query condition
indsindicator list, used as the independent variables (factors) of the regression
返回
the regression result vector in the following format: [alpha, beta1, beta2, ..., betan, e1, e2, ..., en, RSS, R²]
  • alpha: the intercept
  • beta1~betan: the coefficient of every factor
  • e1~en: the residual of every data point (actual value - predicted value)
  • RSS: the residual sum of squares
  • R²: the coefficient of determination An empty vector is returned if the data is insufficient or the regression fails

        the average noise (i.e. within the lookback period, the length by which every low price

Accumulate to the given number of periods; the number of periods from the accumulation forward to the given value until now 

Usage: SUMBARS(X,A): accumulate X forward until it is greater than or equal to A, and return the
number of periods of this interval
For example: SUMBARS(VOL,CAPITAL) gives the number of periods from the full turnover until now
注解
discard semantics (there is a difference between the scalar parameter and the sequence parameter):
  • Scalar parameter SUMBARS(ind, double): if a position is still < a after accumulating to the leftmost end of the sequence, the whole segment is marked as discard (a static global optimization, because when the scalar a is unreachable monotonically the earlier positions are even more unreachable).

That is, the dynamic path does not guarantee "all the values after discard are valid". The downstream should handle it with std::isnan, and should not assume "everything after discard is valid".

Usage: TS_RANK(X,N) means the rank of X within the past N periods divided by the number of the
valid (non-NaN) observations in the window
For example: TS_RANK(CLOSE,20) means the rank ratio of the close price within the past 20 periods

Definition in Alpha101:
TS_RANK(x, n) = (rank of x in the last n observations) / n
where rank is the ascending rank, i.e. the smaller values are ranked first

Implementation description:
For every period i, count the number of the non-NaN elements in the window [i-n+1, i] that are
less than or equal to x[i] (call it valid_le), and the number of the non-NaN elements in the same
window (call it valid). Then TS_RANK = valid_le / valid. If x[i] itself is NaN, TS_RANK is Null;
if the window has any valid observation (which is guaranteed when x[i] is not NaN because x[i]
itself counts), the result is well-defined.

NaN policy: consistent with the library-wide "extreme/mean ignore missing, denominator uses valid
count" convention (see MA, HHV, LLV, STDEV). Missing days are excluded from both the numerator
and the denominator, so a stock with suspension gaps is ranked against the days it actually
traded, not against the calendar slots.

Complexity: each bar runs an O(n) linear scan over the window (per bar parallelized across
days). Realistic measurement (sh000001 daily, total ~5K bars, cycle=100, macOS arm64 release):
n=60 ~0.017 us/bar, n=2000 ~0.079 us/bar; the O(n) cost stays cheap thanks to cache-friendly
sequential access and no incremental order-statistic structure is warranted for typical n <= 200.
参数
nnumber of the periods
