◆ get()

template<typename ResourceType, size_t MAX_POOL_SIZE_LIMIT = 2>
stdx::expected< ResourcePtr, std::string > hku::ResourceTlsPool< ResourceType, MAX_POOL_SIZE_LIMIT >::get ( )
inline

Get an available resource (a synchronous operation)

返回
the expected object of ResourcePtr, it contains the resource pointer on success and the error information on failure
注解
It is a completely lock free operation with an extremely high performance (an O(1) time complexity)
The returned shared_ptr returns the resource to the pool automatically at its destruction (through the custom deleter)
If the current number of the resources has reached the upper limit and there is no idle resource, the error information is returned
This is a synchronous method, it returns immediately when called within the same thread, without waiting
The resource is preferentially got from the idle list of the Ring Buffer; a new one is created if there is none
Execution flow
  1. Check whether the Ring Buffer has an idle resource (m_freeCount > 0)
    • Yes: dequeue it from the head and return the resource pointer
  2. If there is no idle resource, check whether the maximum number of the resources is reached (m_count >= m_maxCount)
    • Yes: return an error
  3. Create a new resource and increase the count

◆ releaseIdleResource()

template<typename ResourceType, size_t MAX_POOL_SIZE_LIMIT = 2>
void hku::ResourceTlsPool< ResourceType, MAX_POOL_SIZE_LIMIT >::releaseIdleResource ( )
inline

Release all the currently idle resources

注解
It traverses all the idle resources in the Ring Buffer and deletes them, subtracting m_freeCount from m_count
This operation releases all the unused resources immediately, but it does not affect the resources in use
It is suitable for the scenarios needing to actively reclaim the memory (such as the idle period of the program)
The time complexity is O(m_freeCount), all the idle resources need to be traversed
