详细描述

Base class of the stop-loss / take-profit strategy

It provides the expected stop-loss price of the current planned trade to the system. The result of the subclass hook is interpreted as follows:

  • > 0: the stop-loss level, expressed in the same (adjusted) price coordinate as the KData passed to setTO; the system maps it back to the original price coordinate
  • 0: no stop-loss on this bar; the trade still takes place, without stop-loss protection
  • negative, NaN or inf: invalid; the level is returned as Null and the system opens the trade without stop-loss (no entry is skipped) The same rule applies when the instance is used as a take-profit, except that 0 or an invalid level only means no take-profit on this bar, the trade is not affected.

◆ _getPrice()

virtual price_t hku::StoplossBase::_getPrice ( const Datetime & datetime,
price_t price )
pure virtual

Subclass interface: compute the planned stop-loss price of the current expected trade (a buy); 0 means no stop-loss.

A negative or non-finite result is invalid: the public getPrice returns Null for it and the system opens the trade without stop-loss. Used as a stop-loss it is called on the entry path only (about once or twice per trade, the level is then fixed in the position record); used as a take-profit it is called once per bar while the position is held. The returned level must use the (adjusted) price coordinate of the KData passed to setTO

Subclass interface: compute the planned stop-loss price of a short sell; default 0 (no short stop-loss is provided).

A negative or non-finite result is invalid: the public getShortPrice returns Null for it and the system opens the short position without stop-loss. Used as a short stop-loss it is called on the entry path only; used as a short take-profit it is called once per bar while the position is held. The returned level must use the (adjusted) price coordinate of the KData passed to setTO.

注解
Unlike a long stop-loss, a short one must be above the planned trade price, and must not fall back to the long-side _getPrice result

◆ getPrice()

price_t hku::StoplossBase::getPrice ( const Datetime & datetime,
price_t price )

Get the planned stop-loss price of the current expected trade (a buy); 0 is returned if there is no stop-loss price.

A negative or non-finite result of the subclass hook is invalid and returned as Null; the system then opens the trade without stop-loss (sized with the full planned price as risk). The system still skips the trade when the level is not lower than the planned buy price. It is used by the system to query the planned stop-loss price of the current trade from the stop-loss strategy module before the trade is executed.

参数
datetimetrade time
pricethe planned buy price
注解
Generally the algorithms of the stop-loss and the take-profit can be interchanged, but the stop-loss can be passed the price of the planned trade, for example taking 30% of the buy price as the stop-loss. The take-profit does not consider the passed price parameter, i.e. it regards price as 0.0. In fact, even for the stop-loss it is not recommended to use the price parameter; for example 30% of the previous day's low price can be used as the stop-loss, then the price parameter does not need to be considered

◆ getShortPrice()

price_t hku::StoplossBase::getShortPrice ( const Datetime & datetime,
price_t price )

Get the planned stop-loss price of the current expected trade (a short sell); 0 is returned if there is no stop-loss price.

A negative or non-finite result of the subclass hook is invalid and returned as Null; the system then opens the short position without stop-loss (sized with the full planned price as risk). The system still skips the trade when the level is not above the planned trade price, since the cover would trigger immediately. It is used by the system to query the planned stop-loss price of the current trade from the stop-loss strategy module before the trade is executed.

参数
datetimetrade date
pricethe planned trade price
注解
Unlike a long stop-loss, a short one must be above the planned trade price. The default implementation returns 0 (no short stop-loss is provided), subclasses supporting short selling must override it; it must not fall back to the long-side getPrice result
